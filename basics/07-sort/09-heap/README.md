# Heap Sort - ヒープソート

## 概要
ヒープソートは**ヒープ**というデータ構造を使ったソートアルゴリズムです。配列を最大ヒープに変換し、ルート（最大値）を末尾と交換してヒープを縮める操作を繰り返します。追加の配列なしで最悪 O(n log n) を保証できるのが特徴です。

## 目的
- 完全二分木を配列で表現する方法（親子のインデックス計算）を身につける
- heapify（sift down）を正確に書けるようにする（16-heap、優先度付きキューの土台）
- ヒープ構築が O(n log n) ではなく O(n) になる理由を理解する
- 「選択ソートの最大値探しをヒープで O(log n) にしたもの」として理解する
- 解ける問題の例: 912 Sort an Array、215 Kth Largest Element in an Array、1046 Last Stone Weight、703 Kth Largest Element in a Stream

## ヒープとは
**ヒープ**は完全二分木で、以下の性質を持ちます：
- **最大ヒープ**: 親ノード >= 子ノード（ルートが最大値）
- **配列で表現**: `left = 2*i + 1`, `right = 2*i + 2`, `parent = (i-1)/2`

```
配列:  [22, 19, 5, 3]
index:   0   1  2  3

ツリー表現:
       22        ← 最大値がルート（index 0）
      /  \
    19    5      ← index 1, 2
   /
  3              ← index 3
```

## アルゴリズムの動き
1. **ヒープ構築**: 配列を最大ヒープに変換
2. **ソート**: ルート（最大値）と最後の要素を交換し、ヒープサイズを縮小して再度ヒープ化

```
[3, 22, 19, 5] の場合

【ヒープ構築】 i = size/2 - 1 = 1 から 0 まで heapify
i=1: 22 と子 5 → 22 の方が大きいのでそのまま
i=0: 3 と子 22, 19 → 22 と交換 → [22, 3, 19, 5]
     さらに 3 と子 5 → 5 と交換 → [22, 5, 19, 3]  ← 最大ヒープ

【ソートフェーズ】
ステップ1: 22と3を交換
          [3, 5, 19 | 22]  ← 22確定
          heapify([3, 5, 19])
          [19, 5, 3 | 22]

ステップ2: 19と3を交換
          [3, 5 | 19, 22]  ← 19確定
          heapify([3, 5])
          [5, 3 | 19, 22]

ステップ3: 5と3を交換
          [3 | 5, 19, 22]  ← 5確定

結果: [3, 5, 19, 22]
```

## コードの解説

### ヒープ化処理（main.cpp:6-23）
```cpp
void heapify(vector<int> &nums, int size, int i)
{
    int largest = i;           // 親ノード
    int left = 2 * i + 1;      // 左の子
    int right = 2 * i + 2;     // 右の子

    // 左の子が親より大きいか
    if (left < size && nums[left] > nums[largest])
        largest = left;

    // 右の子が親より大きいか
    if (right < size && nums[right] > nums[largest])
        largest = right;

    // 親が最大でなければ交換して再帰
    if (largest != i)
    {
        swap(nums[i], nums[largest]);
        heapify(nums, size, largest);
    }
}
```
- 「i の下の部分木はすでにヒープ」という前提で、`nums[i]` を正しい位置まで沈める（sift down）
- `size` を引数で受け取るので、ソートフェーズでヒープの範囲だけを扱える

### ソート処理（main.cpp:25-39）
```cpp
void heapSort(vector<int> &nums)
{
    int size = nums.size();

    // 最大ヒープを構築（最後の親ノードから根に向かって）
    for (int i = size / 2 - 1; i >= 0; i--)
    {
        heapify(nums, size, i);
    }

    // ルートを取り出してソート
    for (int i = size - 1; i >= 0; i--)
    {
        swap(nums[0], nums[i]);     // 最大値を末尾へ
        heapify(nums, i, 0);        // 残り [0, i) をヒープ化
    }
}
```
- 下から構築するので、heapify の前提（子の部分木はヒープ）が常に成り立つ
- 末尾から確定していくので、最大ヒープを使うと昇順になる

## 計算量
- **時間計算量**:
  - 最良: O(n log n)
  - 平均: O(n log n)
  - 最悪: O(n log n)
  - ヒープ構築は O(n)（下の段ほどノードが多いが、沈む距離が短い）
- **空間計算量**: O(1)（イン・プレース。ただしこの実装の heapify は再帰なので O(log n) のスタックを使う）

## 特徴
- **不安定ソート**: 根と末尾を交換するので、同じ値の順序が保たれない
- **保証された性能**: 常にO(n log n)
- **イン・プレース**: 追加の配列が不要
- **クイックソートより遅い**: 離れた要素にアクセスするためキャッシュ効率が悪い

## 使いどころ
- メモリが限られていて、かつO(n log n)を保証したい場合
- 優先度付きキュー（ヒープの応用）
- k番目に大きい/小さい要素を見つける問題（サイズ k のヒープで O(n log k)）
- `std::sort` の内部で、クイックソートの再帰が深くなりすぎたときの切り替え先

## 他のソートとの比較
- **クイックソート vs ヒープソート**:
  - クイックソート: 平均的に速いが、最悪O(n²)
  - ヒープソート: 常にO(n log n)だが、平均的にやや遅い
- **マージソート vs ヒープソート**:
  - マージソート: 安定、追加メモリ必要
  - ヒープソート: 不安定、イン・プレース
- **選択ソート vs ヒープソート**:
  - どちらも「残りから最大値を選んで末尾に確定させる」
  - 最大値探しが O(n) なのが選択ソート、O(log n) なのがヒープソート

## 注意点
- ソートフェーズのループは `i > 0` で十分（`i = 0` のときは自分自身との交換になるだけ）
- `heapify` の再帰は while ループに書き換えられる（スタックを使わず完全に O(1) 空間になる）
- 0-indexed と 1-indexed で親子の式が変わる（1-indexed なら `left = 2i`, `right = 2i + 1`, `parent = i/2`）。混ぜない

## 標準ライブラリ
C++では`std::make_heap`（ヒープ構築）、`std::sort_heap`（ヒープソート）、`std::push_heap` / `std::pop_heap`が `<algorithm>` に、優先度付きキューとして`std::priority_queue`（デフォルトは最大ヒープ）が `<queue>` に提供されています。
