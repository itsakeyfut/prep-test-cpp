# 20. Valid Parentheses：積み重ねたお皿（スタック）を使う解き方

[Problem](https://leetcode.com/problems/valid-parentheses/)

## どんな問題？

`(` `)` `[` `]` `{` `}` の6しゅるいのカッコだけでできた文字列があります。
この **カッコの組み合わせが、正しく閉じられているか** を答える問題です。

正しいといえるのは、次の3つをぜんぶ守っているときです。

1. 開いたカッコは、**同じしゅるい** の閉じカッコで閉じる
2. **あとから開いたカッコから先に** 閉じる
3. 閉じていないカッコや、相手のいない閉じカッコが **のこらない**

```
  ( )          →  ✅ 正しい
  ( ) [ ] { }  →  ✅ 正しい
  { [ ( ) ] }  →  ✅ 正しい（内がわから順に閉じている）
  ( ]          →  ❌ しゅるいがちがう
  ( [ ) ]      →  ❌ 閉じる順番がちがう（[ より先に ( を閉じている）
  ( (          →  ❌ 閉じていないカッコがのこる
```

正しければ `true`、まちがっていれば `false` を返します。

> 算数の式 `{ 2 × [ 3 + ( 4 − 1 ) ] }` で、カッコの対応がおかしくないかチェックするのと同じです。

---

## ふつうに考えると…（となりあったペアを消していくやり方）

いちばんかんたんなのは、**となりあった `()` `[]` `{}` を見つけて消す** のを、消せなくなるまでくりかえす方法です。

```
  { [ ( ) ] }
      ~~~         ← ( ) を消す
  { [ ] }
    ~~~           ← [ ] を消す
  { }
  ~~~             ← { } を消す
  （からっぽ）     → ぜんぶ消えた！ ✅ 正しい
```

これでも答えは出ます。でも、**1回消すたびに、文字列を最初から見なおす** ことになります。
カッコが 1万こあると、何千回も最初から見なおすことになって、たいへんです。

---

## かしこいやり方：「積み重ねたお皿」を使う

### アイデア

ルール2の **「あとから開いたカッコから先に閉じる」** に注目します。
これは、**お皿を積み重ねる** のとそっくりです。

```
  お皿は、上に積んでいく。
  とるときは、いちばん上（さいごに置いたもの）からしかとれない。

       ┌─────┐   ← さいごに置いたお皿。とるならこれから
       ├─────┤
       ├─────┤
       └─────┘   ← さいしょに置いたお皿
```

そこで、**開きカッコを見つけたら、「あとで来るはずの閉じカッコ」を書いたお皿を積みます**。

```
  ( を見つけた → 「 ) 」と書いたお皿を積む
  [ を見つけた → 「 ] 」と書いたお皿を積む
  { を見つけた → 「 } 」と書いたお皿を積む
```

閉じカッコが来たら、**いちばん上のお皿と同じ文字か** をたしかめます。

> 「いま来た閉じカッコは、いちばん上のお皿に書いてある文字と同じかな？
> 同じなら、そのお皿をとる。**ちがったら、まちがい**。」

（C++ では `std::stack` という道具がこの積み重ねたお皿です。）

### やることは、毎回たったの3ステップ

```
① 1文字見る
② 開きカッコ？
      ├─ はい   → 対応する閉じカッコを書いたお皿を積む
      └─ いいえ（閉じカッコ）→ ③へ
③ いちばん上のお皿と、同じ文字？
      ├─ お皿がない、または ちがう → ❌ まちがい（false）
      └─ 同じ → そのお皿をとる

→ 最後まで見たら、お皿がぜんぶなくなっていれば ✅ 正しい（true）
```

## じっさいにやってみよう

`s = "([]{})"` のとき。

### 1回目：「(」

```
  ( [ ] { } )
  ↑
  開きカッコ → 「 ) 」のお皿を積む

  お皿:  │ ) │
         └───┘
```

### 2回目：「[」

```
  ( [ ] { } )
    ↑
  開きカッコ → 「 ] 」のお皿を積む

  お皿:  │ ] │  ← いちばん上
         │ ) │
         └───┘
```

### 3回目：「]」

```
  ( [ ] { } )
      ↑
  閉じカッコ → いちばん上は「 ] 」 → 同じ！ ✅ お皿をとる

  お皿:  │ ) │
         └───┘
```

### 4回目：「{」

```
  ( [ ] { } )
        ↑
  開きカッコ → 「 } 」のお皿を積む

  お皿:  │ } │  ← いちばん上
         │ ) │
         └───┘
```

### 5回目：「}」

```
  ( [ ] { } )
          ↑
  閉じカッコ → いちばん上は「 } 」 → 同じ！ ✅ お皿をとる

  お皿:  │ ) │
         └───┘
```

### 6回目：「)」

```
  ( [ ] { } )
            ↑
  閉じカッコ → いちばん上は「 ) 」 → 同じ！ ✅ お皿をとる

  お皿:  （からっぽ）
```

### 最後のチェック

```
  ぜんぶ見終わった。お皿は のこっていない → 正しい！ ✅ 🎉
```

### まちがいの例：`s = "([)]"`

```
  1回目「(」 → 「 ) 」を積む          お皿: [ ) ]
  2回目「[」 → 「 ] 」を積む          お皿: [ ), ] ]  ← いちばん上は ]
  3回目「)」 → いちばん上は「 ] 」 → ちがう！ ❌

  答え: false
```

`[` を開いたのに、それを閉じる前に `)` が来てしまいました。お皿のおかげで、すぐに気づけます。

## コードとのたいおう

```cpp
bool isValid(std::string s) {
    if (s.size() % 2 != 0) return false;          // 文字の数が奇数なら、ぜったいにペアにならない

    std::stack<char> expectedClosers;             // お皿の山（あとで来るはずの閉じカッコ）
    for (char ch : s) {                           // ① 1文字ずつ見る
        switch (ch) {
            case '(': expectedClosers.push(')'); break;   // ② 開きカッコ → 対応する閉じカッコのお皿を積む
            case '[': expectedClosers.push(']'); break;
            case '{': expectedClosers.push('}'); break;
            default:                                       // ③ 閉じカッコのとき
                if (expectedClosers.empty() || expectedClosers.top() != ch)
                    return false;                          //    お皿がない or ちがう → まちがい
                expectedClosers.pop();                     //    同じ → お皿をとる
        }
    }
    return expectedClosers.empty();               // お皿がぜんぶなくなっていれば正しい
}
```

| コード | 意味 |
|---|---|
| `std::stack<char>` | 積み重ねたお皿の山。上からしか出し入れできない |
| `expectedClosers` | 英語で「来るはずの閉じカッコたち」。お皿に書いてある文字 |
| `push(')')` | `)` と書いたお皿を、いちばん上に積む |
| `top()` | いちばん上のお皿を見る（とらない） |
| `pop()` | いちばん上のお皿をとる |
| `empty()` | お皿が1まいもない？ |
| `s.size() % 2 != 0` | 文字の数を 2 でわって、あまりがある（＝奇数） |

> **くふうポイント**：お皿には開きカッコ `(` ではなく、**来るはずの閉じカッコ `)`** を書いています。
> こうすると、閉じカッコが来たときに `top() != ch` と **そのままくらべるだけ** ですみます。
> 開きカッコを積むやり方だと、「`(` には `)` が対応して…」と、もう一度変換しないといけません。

## 気をつけポイント：最後に「お皿がのこっていないか」をたしかめる

コードの最後は `return true;` ではなく、**`return expectedClosers.empty();`** になっています。

`s = "(("` で考えてみましょう。（文字の数は 2 で偶数なので、最初のチェックは通りぬけます）

もし **最後が `return true;`** だったら…

```
  1回目「(」 → 「 ) 」を積む     お皿: [ ) ]
  2回目「(」 → 「 ) 」を積む     お皿: [ ), ) ]
  ぜんぶ見終わった → true   ❌ まちがい！
```

**閉じていないカッコが2つものこっている** のに、「正しい」と答えてしまいました。
「まちがいが見つからなかった」だけでは、「正しい」とはいえないのです。

**最後に「お皿がからっぽか」をたしかめる** なら、だいじょうぶです。

```
  ぜんぶ見終わった → お皿が 2まい のこっている → false   ✅
```

> もう1つ、閉じカッコが来たときに **`empty()` を先に調べている** のも大事です。
> `s = "))"` のように、お皿が1まいもないのに閉じカッコが来ることがあります。
> `||`（または）は左から順に調べるので、お皿がなければ `top()`（いちばん上を見る）は実行されません。
> **お皿がないのに上を見ようとするのは、C++ ではとてもきけん** なので、この順番を守りましょう。

## どれくらい速くなるの？

カッコの数が **n** のとき、それぞれのやり方で何回くらい文字を見るかをくらべます。

| やり方 | 文字を見る回数 | 1万こなら | むずかしい言い方 |
|---|---|---|---|
| ペアを消していく | 1回消すたびに最初から見なおす → だいたい n × n 回 | 約1億回 | 時間 O(n²) |
| 積み重ねたお皿 | 1文字につき1回 → n 回 | 約1万回 | 時間 O(n) |

そのかわり、お皿の山の分だけ場所（メモリ）を使います。いちばん多いときは、開きカッコの数だけお皿が積まれます（空間 O(n)）。

> **「あとから来たものを、先にかたづける」**
> こういうときは、積み重ねたお皿（スタック）の出番です。
> カッコのチェックのほかにも、「元にもどす（Ctrl+Z）」や、ブラウザの「もどる」ボタンも同じしくみです！
