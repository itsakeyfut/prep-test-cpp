# 13. Roman to Integer：「右どなりとくらべる」ルール1つで解く方法

[Problem](https://leetcode.com/problems/roman-to-integer/)

## どんな問題？

**ローマ数字**（むかしのローマで使われていた数字）を、ふだん使っている数字になおす問題です。

ローマ数字は、7しゅるいの文字でできています。

```
  文字:   I    V    X    L    C     D     M
  数:     1    5    10   50   100   500   1000
```

ふつうは **大きい文字から順に左にならべて、ぜんぶたす** だけです。

```
  III     =  1 + 1 + 1          =  3
  XII     =  10 + 1 + 1         =  12
  LVIII   =  50 + 5 + 1 + 1 + 1 =  58
```

> 時計の文字ばんで「Ⅻ」や「Ⅳ」を見たことがあるかも。あれがローマ数字です。

### でも、とくべつなならび方がある

`4` は `IIII` ではなく **`IV`** と書きます。
**小さい文字が、大きい文字の左にある** ときは「ひき算」になるのです。

```
  IV  =  5 − 1   =  4      （V の左に I → 5 から 1 をひく）
  IX  =  10 − 1  =  9
  XL  =  50 − 10 =  40
  XC  =  100 − 10 = 90
  CD  =  500 − 100 = 400
  CM  =  1000 − 100 = 900
```

---

## ふつうに考えると…（とくべつなならびを、ぜんぶおぼえるやり方）

いちばんかんたんなのは、上の **6つのとくべつなならびを先に探して**、見つけたらまとめて計算する方法です。

```
  M C M X C I V
    ───   ─── ───
    CM    XC  IV   ← とくべつなならびを探す

  M + CM + XC + IV  =  1000 + 900 + 90 + 4  =  1994
```

これでも答えは出ます。でも、**6つのならびをぜんぶおぼえて、1つずつチェック** しないといけません。
ルールが多いと、書きまちがいや見のがしが起きやすくなります。

---

## かしこいやり方：「右どなりとくらべる」

### アイデア

6つのとくべつなならびを、よーく見てみましょう。

```
  I V    X L    C M  ...
  ↑ ↑    ↑ ↑    ↑ ↑
  小 大   小 大   小 大
```

ぜんぶ **「小さい文字の、右どなりに大きい文字」** になっています。
つまり、おぼえるルールは **たった1つ** でいいのです。

> 「いま見ている文字より、**右どなりの文字のほうが大きい**？
> それなら、いまの文字は **ひく**。そうでなければ **たす**。」

### ねだん表を用意する

文字を見たらすぐに数がわかるように、**ねだん表** を作っておきます。

```
┌──────── ねだん表 ────────┐
│  文字  →  数              │
│   I    →   1             │
│   V    →   5             │
│   X    →   10            │
│   L    →   50            │
│   C    →   100           │
│   D    →   500           │
│   M    →   1000          │
└──────────────────────────┘
```

（C++ では `std::unordered_map` という道具がこのねだん表です。）

### やることは、毎回たったの3ステップ

```
① いまの文字と、右どなりの文字の数を、ねだん表で調べる
   （右どなりがないとき＝最後の文字のときは、右どなりを 0 とする）
② くらべる
      ├─ いま ＜ 右どなり → いまの数を ひく ➖
      └─ それ以外         → いまの数を たす ➕
③ 次の文字へ
```

---

## じっさいにやってみよう

`s = "MCMXCIV"`（答えは 1994）のとき。

### 1回目：「M」

```
  M C M X C I V
  ↑
  いま M = 1000   右どなり C = 100

  1000 ＜ 100 ？ → いいえ → たす ➕
  合計:  0 + 1000  =  1000
```

### 2回目：「C」

```
  M C M X C I V
    ↑
  いま C = 100   右どなり M = 1000

  100 ＜ 1000 ？ → はい！ → ひく ➖
  合計:  1000 − 100  =  900
```

### 3回目：「M」

```
  M C M X C I V
      ↑
  いま M = 1000   右どなり X = 10

  1000 ＜ 10 ？ → いいえ → たす ➕
  合計:  900 + 1000  =  1900
```

### 4回目：「X」

```
  M C M X C I V
        ↑
  いま X = 10   右どなり C = 100

  10 ＜ 100 ？ → はい！ → ひく ➖
  合計:  1900 − 10  =  1890
```

### 5回目：「C」

```
  M C M X C I V
          ↑
  いま C = 100   右どなり I = 1

  100 ＜ 1 ？ → いいえ → たす ➕
  合計:  1890 + 100  =  1990
```

### 6回目：「I」

```
  M C M X C I V
            ↑
  いま I = 1   右どなり V = 5

  1 ＜ 5 ？ → はい！ → ひく ➖
  合計:  1990 − 1  =  1989
```

### 7回目：「V」

```
  M C M X C I V
              ↑
  いま V = 5   右どなり → ない（0 とする）

  5 ＜ 0 ？ → いいえ → たす ➕
  合計:  1989 + 5  =  1994

  答え: 1994   🎉
```

まとめると、こうなっています。

```
  文字:   M      C      M      X     C      I     V
  数:    1000   100   1000    10    100     1     5
  計算:   ➕     ➖     ➕     ➖     ➕     ➖     ➕

  +1000 −100 +1000 −10 +100 −1 +5  =  1994
```

とくべつなならびを1つもおぼえていないのに、ちゃんと答えが出ました！

## コードとのたいおう

```cpp
int romanToInt(std::string s) {
    std::unordered_map<char, int> glyph = {          // ねだん表（文字 → 数）
        {'I', 1}, {'V', 5}, {'X', 10}, {'L', 50},
        {'C', 100}, {'D', 500}, {'M', 1000},
    };

    int convertedNumber = 0;                         // 合計（はじめは 0）
    for (int i{0}; i < s.size(); ++i) {              // 左から1文字ずつ見ていく
        int curr = glyph[s[i]];                      // ① いまの文字の数
        int next = (i + 1 < s.size()) ? glyph[s[i + 1]] : 0;  // ① 右どなりの数（ないなら 0）

        if (curr < next) {                           // ② 右どなりのほうが大きい？
            convertedNumber -= curr;                 //    → ひく
        } else {
            convertedNumber += curr;                 //    → たす
        }
    }                                                // ③ 次の文字へ

    return convertedNumber;
}
```

| コード | 意味 |
|---|---|
| `std::unordered_map<char, int> glyph` | ねだん表。文字を入れると数が出てくる |
| `curr` | 英語の current（いまの）。いま見ている文字の数 |
| `next` | 英語で「次の」。右どなりの文字の数 |
| `i + 1 < s.size()` | 右どなりがあるか？（最後の文字なら、右どなりはない） |
| `? glyph[s[i + 1]] : 0` | 右どなりがあればその数、なければ 0 |
| `convertedNumber` | 英語で「変換した数」。ここまでの合計 |

## 気をつけポイント：「＜」と「≦」をまちがえない

ひくかどうかは、**右どなりのほうが「大きい」とき（`<`）だけ** です。
**「同じ」ときはたす** ことに気をつけましょう。

`s = "II"`（答えは 2）で考えてみましょう。

もし **「右どなりが同じか大きいならひく」（`<=`）** だったら…

```
  1回目:  I = 1   右どなり I = 1    1 ≦ 1 → ひく ➖   合計  −1
  2回目:  I = 1   右どなり なし 0   1 ≦ 0 → たす ➕   合計   0

  答え: 0   ❌ まちがい！
```

`II` は `1 + 1 = 2` のはずなのに、0 になってしまいました。
**同じ文字がならぶのは「たし算」** です（`III` = 3、`XX` = 20）。

**「右どなりのほうが大きいときだけひく」（`<`）** なら、だいじょうぶです。

```
  1回目:  I = 1   右どなり I = 1    1 ＜ 1 → いいえ → たす ➕   合計  1
  2回目:  I = 1   右どなり なし 0   1 ＜ 0 → いいえ → たす ➕   合計  2

  答え: 2   ✅
```

> ちなみに `IV` を計算すると、とちゅうの合計が **−1** になります（−1 + 5 = 4）。
> とちゅうでマイナスになっても、最後にはちゃんと正しい答えになるので心配いりません。

---

## どっちがかんたん？

どちらのやり方も、文字を **1回ずつ見るだけ** なので、速さはほとんど同じです。
ちがうのは、**おぼえるルールの数** です。

| やり方 | おぼえるルール | 文字の数が n のとき | むずかしい言い方 |
|---|---|---|---|
| とくべつなならびを探す | 6つ（IV, IX, XL, XC, CD, CM） | だいたい n 回 | 時間 O(n) |
| 右どなりとくらべる | **1つだけ** | だいたい n 回 | 時間 O(n)・空間 O(1) |

※ ねだん表は、文字が何こあっても 7つのままなので、空間は O(1) です。

> **「たくさんのルールの中に、かくれた1つのルールを見つけよう」**
> バラバラに見えるルールも、ならべてみると同じ形をしていることがあります。
> 1つのルールにまとめられると、コードは短く、まちがいも少なくなります！
