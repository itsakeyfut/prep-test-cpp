# 9. Palindrome Number：数字カードを「半分だけ」ならべかえる解き方

[Problem](https://leetcode.com/problems/palindrome-number)

## どんな問題？

ある数が **「回文（かいぶん）」かどうか** を答える問題です。
回文とは、**前から読んでも、うしろから読んでも同じ** になるもののことです。

```
  1 2 3 2 1        →  うしろから読むと  1 2 3 2 1   ✅ 同じ！ 回文
  1 2 3            →  うしろから読むと  3 2 1       ❌ ちがう
 -1 2 1            →  うしろから読むと  1 2 1-      ❌ ちがう（マイナスがうしろに来る）
```

回文なら `true`、ちがうなら `false` を返します。

> 「しんぶんし」「トマト」も回文です。それの **数字バージョン** だと思えば OK！

---

## ふつうに考えると…（ぜんぶひっくり返すやり方）

いちばんかんたんなのは、**数をまるごとうしろから読んだ数を作って、もとの数とくらべる** 方法です。

```
もとの数:      1 2 3 2 1
ひっくり返す:  1 2 3 2 1
くらべる:      同じ → 回文 ✅
```

これでも答えは出ます。でも、ひとつこまったことがあります。

```
もとの数:      2 1 4 7 4 8 3 6 4 7     （int に入る、いちばん大きい数）
ひっくり返す:  7 4 6 3 8 4 7 4 1 2     ← 大きすぎて int に入らない！ 💥
```

C++ の `int` という箱には、入れられる数の大きさに **上限** があります。
ひっくり返した数が、その箱から **あふれてしまう** ことがあるのです。

---

## かしこいやり方：「半分だけ」ひっくり返す

### アイデア

回文は、**左半分と右半分が、鏡（かがみ）のように同じ** です。

```
     1 2 │ 3 │ 2 1
     ───   ↑   ───
     左    まん中  右

  右半分 「2 1」 をうしろから読むと 「1 2」 → 左半分と同じ！
```

だから、ぜんぶひっくり返さなくても、**右半分だけひっくり返して、左半分とくらべれば** わかります。
半分なら、箱からあふれる心配もありません。

### 数字カードでたとえると

数を **数字カードのならび** だと思ってください。
右はしのカードを1まいずつとって、**新しいならび** に置いていきます。

```
  のこりのカード (x)          新しいならび (reversedHalf)
  ┌─┬─┬─┬─┬─┐                ┌┐
  │1│2│3│2│1│   ───→         ││  （からっぽ）
  └─┴─┴─┴─┴─┘                └┘
```

**新しいならびが、のこりのカードと同じくらいの長さになったら** ストップ。
ちょうど半分ひっくり返せたことになります。

### カードをとる道具：「% 10」と「/ 10」

数字カードを1まいとるには、2つの計算を使います。

```
  x = 1 2 3 2 1

  x % 10  →  1          10でわった「あまり」 = いちばん右のカードを見る
  x / 10  →  1 2 3 2    10でわった「答え」   = いちばん右のカードをとりのぞく
```

とったカードを新しいならびの **右に足す** には、こうします。

```
  新しいならび = 新しいならび × 10 + とったカード

  例:  1 2  に  3  を足す →  1 2 × 10 + 3  =  1 2 3
```

### やることは、毎回たったの3ステップ

```
① のこりのカードの、いちばん右を見る        （x % 10）
② それを新しいならびの右に足す              （reversedHalf × 10 + ①）
③ のこりのカードから、いちばん右をとりのぞく （x / 10）

→ 「のこり」が「新しいならび」より大きいあいだ、くりかえす
```

## じっさいにやってみよう

### 例1：`x = 12321`（けた数が「奇数」のとき）

#### 1回目

```
  のこり (x):          1 2 3 2 [1]    ← いちばん右の 1 をとる
  新しいならび:        （からっぽ）

  → のこり: 1 2 3 2      新しいならび: 1
```

#### 2回目

```
  のこり (x):          1 2 3 [2]      ← 2 をとる
  新しいならび:        1

  → のこり: 1 2 3        新しいならび: 1 2
```

#### 3回目

```
  のこり (x):          1 2 [3]        ← 3 をとる
  新しいならび:        1 2

  → のこり: 1 2          新しいならび: 1 2 3
```

#### ストップ！

```
  のこり:        1 2
  新しいならび:  1 2 3      ← のこりより大きくなったので終わり
```

新しいならびには、**まん中の「3」** までいっしょに入っています。
まん中のカードは鏡の「まん中」なので、くらべなくていいカードです。

```
  新しいならび の右はしを とりのぞく:  1 2 3  →  1 2    （reversedHalf / 10）

  のこり 1 2  と  1 2  → 同じ！  回文 ✅ 🎉
```

### 例2：`x = 1221`（けた数が「偶数」のとき）

```
  1回目:  のこり 1 2 2 [1]  →  のこり 1 2 2    新しいならび 1
  2回目:  のこり 1 2 [2]    →  のこり 1 2      新しいならび 1 2
  ストップ（のこり 1 2 は、新しいならび 1 2 より大きくない）

  のこり 1 2  と  新しいならび 1 2  → そのまま同じ！  回文 ✅ 🎉
```

けた数が偶数なら、まん中のカードがないので **そのままくらべればいい** のです。

| けた数 | ストップしたときの形 | くらべ方 |
|---|---|---|
| 偶数（例: 1221） | `12` と `12` | そのままくらべる |
| 奇数（例: 12321） | `12` と `123` | 新しいならびの右はし（まん中）をとってからくらべる |

---

## コードとのたいおう

```cpp
bool isPalindrome(int x)
{
    // 先にはじく：マイナスの数と、右はしが 0 の数（0 そのものはのぞく）
    if (x < 0 || (x % 10 == 0 && x != 0))
        return false;

    int reversedHalf = 0;                              // 新しいならび（はじめはからっぽ）
    while (x > reversedHalf)                           // のこりのほうが大きいあいだ、くりかえす
    {
        reversedHalf = reversedHalf * 10 + x % 10;     // ①② 右はしのカードを、新しいならびに足す
        x /= 10;                                       // ③ のこりから、右はしをとりのぞく
    }

    // 偶数けた：そのままくらべる / 奇数けた：まん中をとってからくらべる
    return x == reversedHalf || x == reversedHalf / 10;
}
```

| コード | 意味 |
|---|---|
| `x % 10` | いちばん右のカード（10でわったあまり） |
| `x /= 10` | いちばん右のカードをとりのぞく（10でわった答えにする） |
| `reversedHalf` | 英語で「ひっくり返した半分」。新しいならびのこと |
| `reversedHalf * 10 + x % 10` | 新しいならびを1つ左にずらして、右にカードを足す |
| `x > reversedHalf` | のこりのほうが大きい = まだ半分まで来ていない |
| `reversedHalf / 10` | 新しいならびから、まん中のカードをとりのぞく |

## 気をつけポイント：「右はしが 0」の数は、先にはじく

コードのいちばん最初で、マイナスの数のほかに **右はしが 0 の数** も `false` にしています。
マイナスがだめなのは、`-` がうしろに来てしまうからでした。では、0 のほうはなぜでしょう？

`x = 10` で考えてみましょう。

もし **右はしが 0 の数をはじかなかったら** …

```
  1回目:  のこり 1 [0]  →  のこり 1    新しいならび 0
                                        （0 を足しても 0 のまま！）
  2回目:  のこり [1]    →  のこり 0    新しいならび 1
  ストップ

  奇数けたのくらべ方:  のこり 0  と  1 / 10 = 0  → 同じ！  回文？  ❌ まちがい！
```

`10` をうしろから読むと `01` です。数としては「1」なので、`10` とはちがいます。
それなのに、**右はしの 0 が新しいならびの中で消えてしまい**、まちがって「回文」と答えてしまいました。

数の **左はしが 0 になることはありません**（`0121` とは書かないですよね）。
だから **右はしが 0 なら、ぜったいに回文ではない** のです。最初にはじいておけば、だいじょうぶです。

```
  x = 10  →  右はしが 0  →  すぐに false  ✅
  x = 0   →  これだけは「0」1まいなので回文。はじかない  ✅
```

## どれくらい速くなるの？

数の **けた数** を d とするとき、くらべてみます。

| やり方 | カードをとる回数 | 10けたなら | あふれる心配 | むずかしい言い方 |
|---|---|---|---|---|
| ぜんぶひっくり返す | d 回 | 10回 | ある 💥 | 時間 O(log n) |
| 半分だけひっくり返す | だいたい d ÷ 2 回 | 5回 | ない ✅ | 時間 O(log n)・空間 O(1) |

※ 数 n のけた数は、だいたい log₁₀ n（n を何回 10 でわれるか）です。だから「むずかしい言い方」では O(log n) になります。

回数は半分になりますが、それよりも大事なのは **箱からあふれない** ことです。
しかも、使う箱は `reversedHalf` の **1つだけ**。文字に変換したりもしないので、とても省エネです。

> **「ぜんぶやらなくても、半分でわかることがある」**
> 回文のように左右が鏡になっているものは、半分だけ調べれば十分です。
> 「もっと少ない手間で同じ答えが出せないかな？」と考えるくせをつけよう！
