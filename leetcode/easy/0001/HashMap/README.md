# 1. Two Sum：メモ帳（ハッシュマップ）を使う解き方

## どんな問題？

数字が一列にならんでいます。この中から **2つえらんで、たすと「目標の数」になる組み合わせ** を見つけて、その2つの **場所の番号** を答える問題です。

```
数字のならび (nums):   [ 4 ,  1 ,  6 ,  5 ]
場所の番号:              0    1    2    3

目標の数 (target): 9
```

`4 + 5 = 9` なので、答えは **場所 0 と 場所 3**、つまり `[0, 3]` です。

> 場所の番号は **0 からはじまる** ことに気をつけよう。

---

## ふつうに考えると…（BruteForce のやり方）

いちばんかんたんなのは、**ぜんぶの組み合わせをためす** 方法です。

```
4 + 1 = 5   ちがう
4 + 6 = 10  ちがう
4 + 5 = 9   ✅ あった！
1 + 6 = 7   （見つかったので、ここから先はためさなくていい）
...
```

これでも答えは出ます。でも数字が 1万こあると、組み合わせはおよそ **5000万とおり** にもなります。たいへんですね。

---

## かしこいやり方：「メモ帳」を使う

### アイデア

数字を **左から1つずつ** 見ていきます。見るたびに、こう考えます。

> 「目標が 9 で、いま 5 を持っている。じゃあ **あと 4 があればいい**。
> 4 って、前に見たことあったっけ？」

これを答えるために、**見た数字と、その場所をメモしておく** のです。

```
┌──────────── メモ帳 ────────────┐
│  数字  →  場所                  │
│   4    →   0                   │
│   1    →   1                   │
│   ...                          │
└────────────────────────────────┘
```

このメモ帳は「数字」を言うと、すぐに「場所」を教えてくれます。
（C++ では `std::unordered_map` という道具がこのメモ帳です。）

### やることは、毎回たったの3ステップ

```
① いまの数字を見る
② 「目標 − いまの数字」（= あといくつ必要か）がメモにあるか調べる
      ├─ ある → 🎉 見つかった！ 答えを返して終わり
      └─ ない → ③へ
③ いまの数字と場所をメモに書いて、次の数字へ
```

---

## じっさいにやってみよう

`nums = [4, 1, 6, 5]`、`target = 9` のとき。

### 1回目：場所 0 の「4」

```
nums:  [ 4 ,  1 ,  6 ,  5 ]
         ↑
        いまここ

あと必要な数 = 9 − 4 = 5
メモ帳: （からっぽ）     → 5 はない ❌

メモに書く:  4 → 0
```

### 2回目：場所 1 の「1」

```
nums:  [ 4 ,  1 ,  6 ,  5 ]
              ↑

あと必要な数 = 9 − 1 = 8
メモ帳: { 4→0 }           → 8 はない ❌

メモに書く:  1 → 1
```

### 3回目：場所 2 の「6」

```
nums:  [ 4 ,  1 ,  6 ,  5 ]
                   ↑

あと必要な数 = 9 − 6 = 3
メモ帳: { 4→0, 1→1 }      → 3 はない ❌

メモに書く:  6 → 2
```

### 4回目：場所 3 の「5」

```
nums:  [ 4 ,  1 ,  6 ,  5 ]
                        ↑

あと必要な数 = 9 − 5 = 4
メモ帳: { 4→0, 1→1, 6→2 } → 4 がある！ 場所は 0 ✅

答え: [0, 3]   🎉
```

数字を **1回ずつ見ただけ** で、答えが見つかりました！

---

## コードとのたいおう

```cpp
std::vector<int> twoSum(std::vector<int>& nums, int target) {
    std::unordered_map<int, int> mp;          // メモ帳を用意する（数字 → 場所）

    for (int i = 0; i < nums.size(); ++i) {   // 左から1つずつ見ていく（i が場所の番号）
        int complement = target - nums[i];    // ② あといくつ必要か計算する
        if (mp.count(complement)) {           //    それがメモにある？
            return {mp[complement], i};       //    ある → メモの場所と、いまの場所を答える
        }
        mp[nums[i]] = i;                      // ③ ない → いまの数字と場所をメモに書く
    }
    return {};                                // 最後まで見つからなかったとき
}
```

| コード | 意味 |
|---|---|
| `std::unordered_map<int, int> mp` | メモ帳。「数字」を入れると「場所」が出てくる |
| `complement` | 英語で「足りない分」という意味。**あと必要な数** のこと |
| `mp.count(complement)` | メモ帳にその数字が書いてあれば 1、なければ 0 |
| `mp[complement]` | メモ帳から、その数字の場所を読む |
| `mp[nums[i]] = i` | メモ帳に「数字 → 場所」を書きこむ |

---

## 気をつけポイント：「調べる」が先、「書く」があと

コードでは **② メモを調べる → ③ メモに書く** の順番になっています。これにはちゃんと理由があります。

`nums = [3, 2, 4]`、`target = 6` で考えてみましょう。

もし **書くのが先** だったら…

```
1回目: 「3」をメモに書く → { 3→0 }
       あと必要な数 = 6 − 3 = 3 → メモにある！ → 答え [0, 0]  ❌ まちがい！
```

**同じ数字を2回使ってしまいました。** 問題では、同じ場所の数字を2回使ってはいけません。

**調べるのが先** なら、だいじょうぶです。

```
1回目: 「3」 あと 3 必要 → メモは空なので、ない → メモに 3→0 を書く
2回目: 「2」 あと 4 必要 → ない                 → メモに 2→1 を書く
3回目: 「4」 あと 2 必要 → ある！ 場所 1         → 答え [1, 2]  ✅
```

---

## どれくらい速くなるの？

数字が **n こ** あるとき、それぞれのやり方で何回くらい調べるかをくらべます。

| やり方 | 調べる回数 | 1万こなら | むずかしい言い方 |
|---|---|---|---|
| ぜんぶためす（BruteForce） | だいたい n × n ÷ 2 回 | 約 5000万回 | 時間 O(n²) |
| メモ帳を使う（HashMap） | だいたい n 回 | 約 1万回 | 時間 O(n) |

そのかわり、メモ帳を使うやり方は **メモ帳の分だけ場所（メモリ）を使います**（空間 O(n)）。

> **「メモをとって、あとで使う」**
> これはプログラミングでとてもよく出てくる考え方です。
> 時間をへらすために、ちょっとだけ場所を使う。おぼえておこう！
